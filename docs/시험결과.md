# 시험용 앱 결과 (차량용)

- 목적: 사양을 확정하기 위해 Pleos 에뮬레이터에서 SDK와 화면 동작을 확인한다 (CLAUDE.md "첫 작업" 1번).
- 시험한 날: 2026-10-31 (1차, R4~R6 화면 캡처 기준), 2026-11-01 (2차, R6. 집 PC 로컬 세션에서 Claude Code가 Virtual Console·adb로 값을 바꾸며 확인)
- 시험한 APK: Releases "개발 최신판"의 `gilteojwo-car_R번호.apk` (R번호는 화면 맨 위에도 표시)
- 결과 칸은 사용자가 알려준 캡처·메모를 보고 Claude가 채운다.

## 준비

1. 에뮬레이터(Pleos_Connect_v2.1.0)를 켠다.
2. GitHub 저장소 → 오른쪽 **Releases** → **개발 최신판** → Assets에서 `gilteojwo-car_R번호.apk`를 받는다.
3. 받은 파일을 에뮬레이터 창에 끌어다 놓아 설치한다. 앱 목록에서 **길터줘**를 연다.
4. 권한 요청 창이 뜨면 모두 **허용**한다.
5. 화면 맨 위 줄을 캡처한다 (R번호, 권한 상태 확인용).
6. Virtual Console을 연다 (http://127.0.0.1:8088/).

화면 구성: 왼쪽은 값이 저절로 바뀌는 항목(①②⑦), 오른쪽은 버튼으로 시험하는 항목(③④⑤⑥).

앱이 꺼졌다가 다시 켜면 맨 위에 빨간 글자로 꺼진 원인이 나온다(안전 모드). 그 글자를 캡처해서 보내고, 항목마다 [이 항목 시작]을 하나씩 눌러 어느 항목에서 꺼지는지 알려준다.

## 확인 순서와 결과

### ① 내 위치 (FusedLocation)

- 화면: Pleos 위치(위도·경도·진행 방향·신뢰도·측정 시각, 받은 횟수)와 안드로이드 기본 위치(위도·경도·속도, 받은 횟수)
- 할 일
  1. 앱을 켠 채로 처음 값을 캡처한다.
  2. 에뮬레이터 옆 도구 막대 **⋯ → Location**에서 지도의 다른 곳(예: 서울시청)을 찍고 **Set location**을 누른다.
  3. **Routes** 탭에서 경로를 만들고 재생한다. 숫자와 진행 방향이 계속 바뀌는지 본다.
- 정하는 것: R-1을 Pleos 위치로 갈지, 안드로이드 기본 위치로 갈지, 둘 다 안 되면 "시연용 내 차 경로"로 갈지

| 확인 | 결과 |
| --- | --- |
| Pleos 위치가 처음에 나오는가 (isSupported, 값) | 나온다. 1초마다 받음(183회). 위도 37.383538, 경도 126.934175, 진행 방향 0°, 신뢰도 5.0 |
| Set location 후 Pleos 값이 바뀌는가 | **바뀐다.** `adb emu geo fix`로 서울시청(37.5665, 126.9780)에 두니 1~2초 안에 같은 좌표로 바뀜 (11/01) |
| 경로 재생 중 Pleos 값과 진행 방향이 계속 바뀌는가 | 1초마다 위치를 옮기면 위도·경도는 따라 바뀐다. **진행 방향은 북쪽·동쪽으로 옮겨도 계속 0°.** 에뮬레이터 GPS 원래 값도 bear=0.0이라 에뮬레이터 입력의 한계로 보임. 에뮬레이터 Routes 재생은 아직 안 해 봄 |
| 안드로이드 기본 위치도 바뀌는가 | **바뀐다** (Pleos와 같은 좌표). 속도는 위치 명령에 속도 값을 넣었을 때만 나온다 (40노트 → 74.1 km/h). 진행 방향은 역시 0 |

### ② 주행 중 화면 제한

- 화면: 주행 제한 걸림(예/아니오), 우리 화면을 주행용으로 인정(true/false), 화면이 가려진 횟수
- 할 일
  1. Virtual Console에서 안전벨트 경고가 있으면 끈다 (Safety → Telltales).
  2. 브레이크를 밟고 기어를 **D**로 바꾼다. 화면에 ACCEL이 있으면 누르고 있는다.
  3. 우리 앱이 "주행 중 사용 불가" 같은 화면에 가려지는지 본다. 가려지면 그 화면을 캡처한다.
  4. 기어를 **P**로 돌린 뒤 '가려진 횟수'가 늘었는지 본다.
- 참고: 기어가 안 바뀌면 집 PC 로컬 세션에서 Claude Code가 `adb shell cmd hmg_car_service --service drivingstate driving_regulation on` 으로 주행 제한을 강제로 켤 수 있다 (Pleos ADB 안내 문서).

| 확인 | 결과 |
| --- | --- |
| P 상태의 주행 제한 값 | 제한 없음 (제한 코드 0) |
| D(주행) 상태의 주행 제한 값 | **제한 걸림 (제한 코드 80).** 기어가 P를 벗어나는 순간(R)부터 걸린다 |
| 우리 화면을 주행용으로 인정하는가 | **false** (매니페스트에 distractionOptimized=true를 선언해도 직접 설치한 앱은 인정 안 됨. 참가자 보고와 같음). 단, 홈 화면 로그에는 우리 앱이 distractionOptimized: true로 찍힘 |
| 주행 중 앱 화면이 가려지는가 | **에뮬레이터에서는 안 가려진다.** 기어 D, 속도 65~200 km/h에서도 길터줘 화면이 그대로 보이고 버튼도 눌린다. 기어를 R로 바꿀 때만 후방 카메라 화면에 한 번 가려짐(가려진 횟수 1) |

### ③ 앰비언트 라이트

- 화면: 지원 범위(켜기·끄기, 밝기 범위, 색 변경 구역)와 최근 명령 결과 6줄
- 할 일
  1. 앱이 켜지면 자동으로 조회한 결과를 캡처한다. 다시 보려면 [지원 범위 조회].
  2. [켜기] [끄기] [빨강] [주황] [흰색] [밝기 최대] [밝기 최소]를 하나씩 누르며 Virtual Console의 앰비언트 표시가 바뀌는지 본다.
  3. [왼쪽만 빨강]으로 구역별 제어가 되는지 본다.
  4. 마지막에 [원래대로].
- 정하는 것: R-15에서 "그쪽만 붉게"가 가능한지, 빨강을 쓸 수 있는지

| 확인 | 결과 |
| --- | --- |
| 지원 구역 (좌석 영역 목록) | **구역 1개** (1열좌·1열우·2열좌·2열중·2열우를 묶은 하나). 켜기·끄기 READ_WRITE [AUTOMATIC, ON, OFF], 밝기 READ_WRITE 0~100, 색 READ_WRITE → 좌우 구역별 제어 불가 |
| 켜기·끄기가 Virtual Console에 반영되는가 | 명령은 "성공"이고 보내는 값도 맞다(SDK의 OFF=0, ON=1). 그런데 **Virtual Console 표시는 계속 On.** 에뮬레이터 쪽 표시 문제로 보임 |
| 빨강을 보냈을 때 성공하는가, Virtual Console에 무슨 색이 보이는가 | R4: 실패 "need Permission" → 바꾸기에는 CONTROL_CAR_LIGHTS 권한이 필요 (설명서와 다름). **R6: 빨강(#FF0000)·흰색·밝기 100 모두 "성공" 응답.** 11/01 재연결 후: **차의 앰비언트 색이 실제로 #ff0000(빨강)으로 바뀐다** (Virtual Console 상태와 차량 조명 로그 모두). 주황(#ff8000)·흰색도 그대로 반영. 주행 중(113 km/h)에도 됨. [원래대로]로 처음 색(#00e5ff)으로 돌아감 |
| 밝기 범위와 반영 여부 | 0~100. **밝기 0 → 0%, 100 → 100%로 반영된다** |
| 왼쪽만 빨강 (구역별 제어) | 구역이 하나뿐이라 불가 |

### ⑥ 내비 위 알림

- 할 일
  1. [10초 뒤 상단 알림]을 누르고 10초 안에 내비를 연다. 10초 뒤 내비 위에 알림 카드가 뜨는지 본다. [10초 뒤 상단 알림 (내비 종류)]도 같은 방법으로 해 본다.
  2. [‘다른 앱 위에 표시’ 허용하러 가기]로 권한을 켠다. 설정 화면이 없다고 나오면 로컬 세션에서 Claude Code가 `adb shell appops set --user 10 com.gilteojwo.car SYSTEM_ALERT_WINDOW allow`로 허용한다 (앱이 차량 사용자 10번으로 돌아서 `--user 10`이 필요).
  3. [10초 뒤 화면 덮기]를 누르고 내비를 연다. 10초 뒤 화면 위쪽에 빨간 띠가 5초 동안 보이는지 본다.
  4. 가능하면 기어 D 상태에서 한 번 더 해 본다.

| 확인 | 결과 |
| --- | --- |
| 상단 알림이 내비 위에 보이는가 | **안 보인다.** 알림 자체는 올라가지만(중요도 높음), 차량 알림 관리자가 "category not set"이라며 위쪽 카드를 띄우지 않는다. 차량용 안드로이드는 일반 앱 알림 중 통화·내비 같은 종류(category)를 단 것만 위쪽 카드로 띄우는 것으로 보임 |
| 종류를 '내비'로 넣은 상단 알림은 보이는가 | **보인다** (11/01, 집 PC 빌드). `Notification.CATEGORY_NAVIGATION`을 넣으니 내비 화면 위쪽에 "구급차 접근 (시험)" 카드가 떴다가 약 8초 뒤 저절로 사라짐. 기어 P와 기어 D·주행 중(22 km/h) 모두 같음. 참고: 기어를 P→D로 바꿀 때 직전 카드가 다시 떠서, 누를 때까지 25초 넘게 남은 적이 한 번 있었다 |
| 화면 덮기(빨간 띠)가 내비 위에 보이는가 | **보인다.** 권한을 허용한 뒤, 내비 화면 위쪽에 빨간 띠가 화면 전체 폭(왼쪽 주행 화면 포함)으로 5초 동안 보임 |
| 기어 D에서도 보이는가 | **보인다** (기어 D, 주행 제한 걸린 상태, 속도 0) |

- 화면: 속도(표준), 기어(표준), 브레이크 페달(Pleos), 방향지시등(Pleos)의 현재 값과 바뀐 시각
- 할 일: Virtual Console에서 하나씩 바꾸고 앱 값이 따라 바뀌는지 본다.
  - Motion → Brake Pedal: 0 → 100%
  - Convenience → Turn Signal State: 왼쪽 / 오른쪽 / 끔
  - Motion → Gear Selection: P → R → N → D
  - 기어 D에서 ACCEL (속도)

| 확인 | 결과 |
| --- | --- |
| 브레이크 페달 | **바뀐다.** 100%로 하면 '밟음', 0%로 하면 '안 밟음' (2~3초 안) |
| 방향지시등 | **바뀐다.** 왼쪽 / 오른쪽 / 꺼짐 모두 그대로 |

## 진행 기록

- R2: 권한 허용 직후 앱이 꺼짐. 원인은 ④ Pleos TTS 호출 순서 오류(initialize 전에 addEventListener). R2에는 오류 방지 장치가 없어 앱 전체가 꺼졌다.
- R3~R4: 오류 방지 장치와 진단 기능을 넣어 앱이 열림. 위 표의 1차 결과를 얻음.
- R6: TTS 순서 수정, CONTROL_CAR_LIGHTS 권한 추가, 글자 크게. 7개 항목 모두 시작됨.
- R6 시험 중 발견: **Virtual Console이 에뮬레이터와 연결이 끊겨 있었다.** 화면 아래에 "HTTP OFFLINE", Turn Signal 카드에 "Failed to fetch"가 떴다. Virtual Console에는 기어 D·110 km/h로 보이는데, 에뮬레이터 계기판과 앱은 P·0 km/h였다. 그래서 Virtual Console에서 바꾼 값이 차에 전달되지 않았다. 이전에 "기어 D 안 됨"이라고 했던 것도 같은 원인일 가능성이 높다. 에뮬레이터를 다시 켜면 포트 연결(adb forward tcp:8088 tcp:8088)이 사라지므로, 다시 연결한 뒤 브라우저를 새로고침해야 한다.
- 11/01 "눌러도 안 켜짐" 확인 (집 PC 로컬 세션, logcat·충돌 기록): 00:41~00:47에 에뮬레이터에 깔려 있던 판이 R2여서 누를 때마다 2초 안에 꺼졌다(위 R2와 같은 TTS 순서 오류, 10회). R6과 집 PC 빌드(R1, 커밋 local)는 앱 목록 아이콘 누르기, 실행 중 다시 누르기, 완전히 끈 뒤 누르기 모두 정상으로 열린다. 코드 수정은 필요 없었다.
- 11/01 2차 시험 (R6, 집 PC 로컬 세션): Virtual Console을 다시 연결하니 화면 아래가 "DDS ONLINE"이었다. Claude Code가 Virtual Console·adb로 값을 바꾸며 ①②③⑥⑦을 확인해 위 표를 채웠다. 끝난 뒤 기어 P, 위치(시흥동), 앰비언트 색을 원래대로 돌려 놓았고, '다른 앱 위에 표시' 허용은 켜 둔 채로 두었다.
- 덤으로 본 것: 앱을 새로 켤 때마다 안드로이드 TTS가 "초기화 실패 (상태 -1)"로 나온다(R6, 집 PC 빌드 모두). Pleos TTS는 매번 초기화 성공.
- 11/01 시험 앱 ⑥에 [10초 뒤 상단 알림 (내비 종류)] 버튼 추가. 집 PC 빌드로 확인했고, 다음 GitHub 시험판부터 들어간다.

## 결론 (시험 후 작성)

지금까지 확정된 것 (R6 기준):
- R-12 음성: Pleos TTS(ON_DEVICE) 한국어가 에뮬레이터에서 나온다. 1순위로 쓴다. 안드로이드 TTS는 예비.
  지직거리는 잡음은 에뮬레이터의 소리 출력 특성일 수 있어 실차와 다를 수 있다. 같은 PC에서 내비·음악 소리도 지직거리는지 비교해 볼 것.
- R-12 좌우 알림음: 코드로 만든 소리를 왼쪽·오른쪽 한쪽에서만 내는 것이 된다. "오는 쪽 스피커에서 알림음"을 그대로 간다.
- R-15 앰비언트: 조명 구역이 하나뿐이라 좌우 구분은 불가. 전체 색으로 단계 표시(관심 주황, 경고 빨강, 양보 빨강 깜빡임)로 간다. 바꾸기에는 CONTROL_CAR_LIGHTS 권한이 필요하다. **색(빨강 포함)과 밝기는 차에 실제로 반영된다(11/01).** 켜기·끄기는 Virtual Console에 안 보이므로, 끌 때는 처음에 저장한 색·밝기로 되돌리는 방식이 안전하다.
- R-9·R-10 주행 중 화면: 시스템은 우리 화면을 주행용으로 인정하지 않는다(false). 그래도 에뮬레이터에서는 기어 D·주행 중에 앱 화면이 가려지지 않고 버튼도 눌린다. 실차는 다를 수 있으니, 알림은 앱 화면에만 기대지 말고 아래 '화면 덮기'를 같이 쓴다.

11/01 2차 시험으로 정할 수 있는 것 (사양서 반영은 사용자 확인 후):
- R-1 내 위치: Pleos 위치·안드로이드 위치 모두 에뮬레이터 위치를 따라간다. 진행 방향은 에뮬레이터에서 0°로만 나오므로, 앞뒤 두 위치로 직접 계산하는 방식을 함께 준비한다. 속도는 차량 속도(PERF_VEHICLE_SPEED)를 쓴다.
- 차량 상태(양보 행동 안내): 브레이크·방향지시등·기어·속도가 모두 2~3초 안에 따라온다. 그대로 쓸 수 있다.
- 내비 위 알림: 종류 없는 상단 알림은 내비 위에 뜨지 않는다. **종류를 '내비'로 넣은 상단 알림은 내비 위에 뜬다**(기어 P·D 모두, 약 8초). '화면 덮기'(다른 앱 위에 표시)도 내비 위, 기어 D에서 보인다.
  - 내비 종류 상단 알림: 따로 권한이 필요 없다. 다만 긴급차량 알림에 '내비' 종류를 붙여도 되는지(심사·정책) 확인이 필요하다.
  - 화면 덮기: 크고 오래 보여 줄 수 있다. 다만 이 권한은 직접 설치한 앱에서 adb로 켜야 했으니 실차·심사 환경에서 어떻게 켜지는지 주최 측에 확인이 필요하다.
  - 두 가지 중 무엇을 쓸지(또는 둘 다 쓸지)는 사용자가 정한다.

남은 시험:
- 에뮬레이터 Routes(경로) 재생 중 진행 방향이 바뀌는지
- 속도가 있을 때(주행 중) 화면 덮기가 보이는지
- 안드로이드 TTS 처음 초기화 실패(-1) 원인
