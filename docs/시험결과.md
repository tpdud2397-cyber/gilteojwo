# 시험용 앱 결과 (차량용)

- 목적: 사양을 확정하기 위해 Pleos 에뮬레이터에서 SDK와 화면 동작을 확인한다 (CLAUDE.md "첫 작업" 1번).
- 시험한 날: 2026-10-31 (1차, R4 화면 캡처 기준. 값 바꾸기 시험은 아직)
- 시험한 APK: Releases "개발 최신판"의 `gilteojwo-car_R번호.apk` (R번호는 화면 맨 위에도 표시)
- 결과 칸은 사용자가 알려준 캡처·메모를 보고 Claude가 채운다.

## 준비

1. 에뮬레이터(Pleos_Connect_v2.1.0)를 켠다.
2. GitHub 저장소 → 오른쪽 **Releases** → **개발 최신판** → Assets에서 `gilteojwo-car_R번호.apk`를 받는다.
3. 받은 파일을 에뮬레이터 창에 끌어다 놓아 설치한다. 앱 목록에서 **길터줘**를 연다.
4. 권한 요청 창이 뜨면 모두 **허용**한다.
5. 화면 맨 위 줄을 캡처한다 (R번호, 권한 상태 확인용).
6. Virtual Console을 연다 (http://127.0.0.1:8088/).

화면 구성: 왼쪽은 값이 저절로 바뀌는 항목(①②⑦), 오른쪽은 버튼으로 시험하는 항목(③④⑤⑥).

앱이 꺼졌다가 다시 켜면 맨 위에 빨간 글자로 꺼진 원인이 나온다(안전 모드). 그 글자를 캡처해서 보내고, 항목마다 [이 항목 시작]을 하나씩 눌러 어느 항목에서 꺼지는지 알려준다.

## 확인 순서와 결과

### ① 내 위치 (FusedLocation)

- 화면: Pleos 위치(위도·경도·진행 방향·신뢰도·측정 시각, 받은 횟수)와 안드로이드 기본 위치(위도·경도·속도, 받은 횟수)
- 할 일
  1. 앱을 켠 채로 처음 값을 캡처한다.
  2. 에뮬레이터 옆 도구 막대 **⋯ → Location**에서 지도의 다른 곳(예: 서울시청)을 찍고 **Set location**을 누른다.
  3. **Routes** 탭에서 경로를 만들고 재생한다. 숫자와 진행 방향이 계속 바뀌는지 본다.
- 정하는 것: R-1을 Pleos 위치로 갈지, 안드로이드 기본 위치로 갈지, 둘 다 안 되면 "시연용 내 차 경로"로 갈지

| 확인 | 결과 |
| --- | --- |
| Pleos 위치가 처음에 나오는가 (isSupported, 값) | 나온다. 1초마다 받음(183회). 위도 37.383538, 경도 126.934175, 진행 방향 0°, 신뢰도 5.0 |
| Set location 후 Pleos 값이 바뀌는가 | |
| 경로 재생 중 Pleos 값과 진행 방향이 계속 바뀌는가 | |
| 안드로이드 기본 위치도 바뀌는가 | 처음 값은 Pleos와 같은 좌표로 나온다(158회, 속도 0.0). 바뀌는지는 아직 |

### ② 주행 중 화면 제한

- 화면: 주행 제한 걸림(예/아니오), 우리 화면을 주행용으로 인정(true/false), 화면이 가려진 횟수
- 할 일
  1. Virtual Console에서 안전벨트 경고가 있으면 끈다 (Safety → Telltales).
  2. 브레이크를 밟고 기어를 **D**로 바꾼다. 화면에 ACCEL이 있으면 누르고 있는다.
  3. 우리 앱이 "주행 중 사용 불가" 같은 화면에 가려지는지 본다. 가려지면 그 화면을 캡처한다.
  4. 기어를 **P**로 돌린 뒤 '가려진 횟수'가 늘었는지 본다.
- 참고: 기어가 안 바뀌면 집 PC 로컬 세션에서 Claude Code가 `adb shell cmd hmg_car_service --service drivingstate driving_regulation on` 으로 주행 제한을 강제로 켤 수 있다 (Pleos ADB 안내 문서).

| 확인 | 결과 |
| --- | --- |
| P 상태의 주행 제한 값 | 제한 없음 (제한 코드 0) |
| D(주행) 상태의 주행 제한 값 | |

| 주행 중 앱 화면이 가려지는가 | |

### ③ 앰비언트 라이트

- 화면: 지원 범위(켜기·끄기, 밝기 범위, 색 변경 구역)와 최근 명령 결과 6줄
- 할 일
  1. 앱이 켜지면 자동으로 조회한 결과를 캡처한다. 다시 보려면 [지원 범위 조회].
  2. [켜기] [끄기] [빨강] [주황] [흰색] [밝기 최대] [밝기 최소]를 하나씩 누르며 Virtual Console의 앰비언트 표시가 바뀌는지 본다.
  3. [왼쪽만 빨강]으로 구역별 제어가 되는지 본다.
  4. 마지막에 [원래대로].
- 정하는 것: R-15에서 "그쪽만 붉게"가 가능한지, 빨강을 쓸 수 있는지

## 진행 기록

- R2: 권한 허용 직후 앱이 꺼짐. 원인은 ④ Pleos TTS 호출 순서 오류(initialize 전에 addEventListener). R2에는 오류 방지 장치가 없어 앱 전체가 꺼졌다.
- R3~R4: 오류 방지 장치와 진단 기능을 넣어 앱이 열림. 위 표의 1차 결과를 얻음.
- R6: TTS 순서 수정, CONTROL_CAR_LIGHTS 권한 추가, 글자 크게. 7개 항목 모두 시작됨.
- R6 시험 중 발견: **Virtual Console이 에뮬레이터와 연결이 끊겨 있었다.** 화면 아래에 "HTTP OFFLINE", Turn Signal 카드에 "Failed to fetch"가 떴다. Virtual Console에는 기어 D·110 km/h로 보이는데, 에뮬레이터 계기판과 앱은 P·0 km/h였다. 그래서 Virtual Console에서 바꾼 값이 차에 전달되지 않았다. 이전에 "기어 D 안 됨"이라고 했던 것도 같은 원인일 가능성이 높다. 에뮬레이터를 다시 켜면 포트 연결(adb forward tcp:8088 tcp:8088)이 사라지므로, 다시 연결한 뒤 브라우저를 새로고침해야 한다.
- 11/01 "눌러도 안 켜짐" 확인 (집 PC 로컬 세션, logcat·충돌 기록): 00:41~00:47에 에뮬레이터에 깔려 있던 판이 R2여서 누를 때마다 2초 안에 꺼졌다(위 R2와 같은 TTS 순서 오류, 10회). R6과 집 PC 빌드(R1, 커밋 local)는 앱 목록 아이콘 누르기, 실행 중 다시 누르기, 완전히 끈 뒤 누르기 모두 정상으로 열린다. 코드 수정은 필요 없었다.

## 결론 (시험 후 작성)

지금까지 확정된 것 (R6 기준):
- R-12 음성: Pleos TTS(ON_DEVICE) 한국어가 에뮬레이터에서 나온다. 1순위로 쓴다. 안드로이드 TTS는 예비.
  지직거리는 잡음은 에뮬레이터의 소리 출력 특성일 수 있어 실차와 다를 수 있다. 같은 PC에서 내비·음악 소리도 지직거리는지 비교해 볼 것.
- R-12 좌우 알림음: 코드로 만든 소리를 왼쪽·오른쪽 한쪽에서만 내는 것이 된다. "오는 쪽 스피커에서 알림음"을 그대로 간다.
- R-15 앰비언트: 조명 구역이 하나뿐이라 좌우 구분은 불가. 전체 색으로 단계 표시(관심 주황, 경고 빨강, 양보 빨강 깜빡임)로 간다. 바꾸기에는 CONTROL_CAR_LIGHTS 권한이 필요하다. Virtual Console에서 실제 색이 바뀌는지는 재연결 후 확인.
- R-9·R-10 주행 중 화면: 시스템이 우리 화면을 주행용으로 인정하지 않는다(false). 실제로 가려지는지는 Virtual Console 재연결 후 기어 D에서 확인.

남은 시험: Virtual Console 재연결 후 ⑦ 값 바꾸기, ② 기어 D, ③ 색 반영, ① 위치 옮기기, ⑥ 내비 위 알림.
