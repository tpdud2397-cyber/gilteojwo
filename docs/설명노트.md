# 길터줘 코드 설명 노트

2차 PT 기술 Q&A 대비용. 모듈별로 "무엇을, 왜" 했는지 적는다. 코드가 바뀌면 같이 고친다.

## 전체 구조

- 한 프로젝트에서 설치 파일(APK) 두 개를 만든다. 이 설정을 product flavor라고 한다.
  - `phone` (폰용, 송신): 지금은 "준비 중" 화면 하나. Pleos SDK를 넣지 않는다.
  - `car` (차량용, 수신 + Pleos 송신 모드): 본 화면 "길터줘"와 SDK 시험 화면 "길터줘 시험". Pleos SDK를 넣는다.
- 폴더
  - `app/src/main`: 두 앱이 함께 쓰는 것 (앱 이름, 아이콘, 빌드 정보, 거리·방향·접근 계산)
  - `app/src/phone`: 폰용만
  - `app/src/car`: 차량용만 (권한 선언, Pleos 위치 받기, 본 화면, 시험 화면)
  - `app/src/test`: 계산이 맞는지 PC에서 자동으로 확인하는 시험
- 앱 ID가 `com.gilteojwo.phone`, `com.gilteojwo.car`로 달라서 한 기기에 둘 다 설치할 수 있다.

## 빌드와 배포

- main에 올리면 GitHub Actions(`.github/workflows/build.yml`)가 두 APK를 만들어 Releases의 "개발 최신판"을 새 파일로 바꾼다.
- APK 파일 이름 뒤에 _R번호(GitHub 빌드 번호)를 붙이고, 화면 맨 위에도 같은 R번호와 커밋 번호를 보여준다. 받은 파일과 깔린 앱이 같은지 바로 알 수 있다.
- 집 PC에서 만든 판은 R번호가 없어서 "PC 빌드 (11/01 11:51)"처럼 만든 시각을 보여준다 (`app/build.gradle.kts`의 buildLabel). PC에서는 커밋하기 전에 빌드하는 일이 많아서, 커밋 번호보다 만든 시각이 더 정확하다.
- GitHub 빌드는 APK를 만들기 전에 계산 시험(`app/src/test`)을 먼저 돌린다. 하나라도 틀리면 APK를 만들지 않아서, 계산이 틀린 판이 나가지 않는다.
- 개발용 서명 키(`app/debug.keystore`)를 저장소에 넣었다. 매번 같은 도장이 찍혀서 지우지 않고 덮어 설치할 수 있다. 시험판 전용이고 비밀이 아니다. 제출용 정식판은 별도 키를 GitHub Secrets에 둔다.
- Pleos SDK는 Pleos Maven 저장소에서 받는다. 위치 SDK는 저장소에 1.1.3만 있어서 1.1.3을 쓴다 (문서에는 1.1.2로 적혀 있음).

## 본 개발 1단계: 내 위치 → 긴급차량 수신 → 거리·방향·도착 시간 → 접근 판정 (R-1~R-4)

사양서의 다섯 모듈 중 "내 위치", "긴급차량 수신", "접근 판정"을 먼저 만들었다. 계산 부분은 안드로이드에 기대지 않는 순수한 코드로 만들어서 PC에서 자동 시험으로 확인한다.

| 권한 | `permission/PermissionHelper` (차량용) | 아직 없는 권한만 요청 | 본 화면과 시험 화면이 같이 쓴다 (시험 폴더에서 옮김) |

### 계산 방법 (발표용 한 줄 설명)

- **거리**: 지구를 반지름 6,371km 공으로 보고 두 점 사이 곡선 거리를 구한다 (하버사인 공식).
- **방위**: A에서 B를 바라보는 방향. 북쪽 0°, 동쪽 90°, 남쪽 180°, 서쪽 270°.
- **어느 쪽인가**: (긴급차량 방위 − 내 진행 방향)이 0° 근처면 전방, 90° 근처면 우측, 180° 근처면 후방, 270° 근처면 좌측.
- **도착 시간**: 5초 전보다 몇 m 가까워졌는지로 "1초에 몇 m씩 오는지"를 구하고, 남은 거리를 그 값으로 나눈다. 1초에 0.5m보다 적게 가까워지면 GPS 흔들림으로 보고 도착 시간을 내지 않는다.
- **접근 중**: ① 거리가 줄고 있고 ② 긴급차량의 진행 방향과 '긴급차량에서 나를 보는 방향'의 차이가 60° 이내. 둘 다 맞아야 한다.
- 기준값(3m, 5초, 0.5m/초, 60°)은 제안값이고 시연 후 조정한다.

### 서버 (Supabase, 도쿄 지역)

- 표 4개 (사양서 '서버'와 같다)
  - `vehicles` 등록 차량: 차량 ID, 등록 코드(비밀), 종류, 운용 기관, 사용 여부
  - `dispatches` 출동 기록: 시작·종료 시각, 종료 방식(수동·자동), 출처. 이동 경로는 저장하지 않는다
  - `positions_live` 긴급차량 현재 위치: 차량당 한 줄. 이 표가 바뀌면 수신 앱에 실시간으로 간다
  - `yield_acks` 양보 확인(익명): 차량 ID 없이 대략 위치와 상태만. 출동이 끝나면 지운다
- `positions_active`: 최근 10초 안에 갱신된 차만 보여주는 목록 (앱을 처음 켤 때 쓴다)
- 잠금(RLS): 모든 표를 잠그고 공개 키에는 두 가지만 연다. ① 현재 위치 읽기 ② 양보 확인 쓰기. 등록 차량 표는 공개 키로 읽어도 빈 목록이 나온다 (등록 코드 보호).
- 송신용 기능 3개 (등록 코드가 맞을 때만 동작)
  - `start_dispatch(p_reg_code)` → 출동 ID. 끝나지 않은 이전 출동은 '자동 종료'로 닫는다
  - `send_position(p_reg_code, p_dispatch_id, p_latitude, p_longitude, p_heading, p_speed_kmh, p_accuracy_m)` → 현재 위치 한 줄을 넣거나 고친다
  - `end_dispatch(p_reg_code, p_dispatch_id, p_end_type)` → 현재 위치를 바로 지우고 종료 시각을 남기고 양보 확인을 지운다
- 표를 만든 SQL은 사용자가 Supabase SQL 편집기에서 실행했다 (2026-11-01). 시험용 구급차 `TEST-AMB-1`이 등록돼 있다. 등록 코드는 비밀이라 저장소에 적지 않는다.

### 시험 도구: 가짜 구급차 (`tools/fake_ambulance.py`)

- 송신 앱이 생기기 전에 수신 앱을 확인하려고 만든 파이썬 스크립트. 서버의 송신용 기능을 1초마다 불러 구급차가 내 차 뒤 600m에서 시속 60km로 다가와 지나가게 한다. 끝나면 긴급출동을 종료한다.
- 11/01 확인 결과 (에뮬레이터, `adb logcat -s Gilteojwo`): 약 1.2초마다 계산했고, "후방 550m · 약 44초 · 접근 중" → … → "후방 33m · 약 3초 · 접근 중" → 지나간 뒤 "전방 33m · 접근 아님" → 출동 종료 후 "0대".
- 주의: 화면 글자를 읽는 도구(uiautomator)를 자주 돌리면 앱 화면이 늦게 바뀌는 것처럼 보인다. 확인은 로그로 한다.

### 자동 시험 (`app/src/test`)

- 시험 이름이 곧 설명이다. 예: "뒤에서 1초에 20m씩 다가오면 접근 중이고 약 24초 뒤 도착", "거리가 줄어도 내 쪽을 향해 오지 않으면 접근 중이 아니다".
- 25개 (GeoMath 8, RelativeDirection 6, HeadingFromMovement 3, ApproachTracker 5, VehicleType 3). 서울시청을 기준점으로 쓴다.
- 시험을 먼저 쓰고, 계산이 비어 있을 때 실패하는 것을 확인한 다음 계산을 채워 통과시켰다. 시험이 틀린 값을 실제로 잡아낸다는 증거다.
- 실행: `./gradlew testCarDebugUnitTest` (GitHub 빌드에서도 자동으로 돈다).

### 어떤 값을 어디서 읽는가 (Pleos 문서 기준)

- 속도: 안드로이드 표준 `PERF_VEHICLE_SPEED`. Pleos FAQ에 "계기판이 이 값을 쓴다"고 되어 있다.
- 기어: 안드로이드 표준 `GEAR_SELECTION`. Pleos Vehicle SDK의 기어 API는 "표준 GEAR_SELECTION을 쓰라"며 폐지 예정이다.
- 브레이크 페달, 방향지시등, 앰비언트 라이트: Pleos Vehicle SDK (`Brake`, `TurnSignal`, `Light`).
- 위치: Pleos FusedLocation SDK. 진행 방향은 있지만 속도는 없다.
- 음성: Pleos TextToSpeech SDK, ON_DEVICE 모드 (앱 등록 불필요).

### 권한

- Pleos Vehicle 권한(`CAR_DRIVE`, `CAR_LIGHTS`)은 'normal' 등급이라 선언만 하면 된다. 앰비언트 라이트 바꾸기는 `CONTROL_CAR_LIGHTS`가 필요하다 (설명서에는 CAR_LIGHTS로 적혀 있지만 실제 SDK 코드가 CONTROL_CAR_LIGHTS를 검사한다).
- Pleos 위치(`FUSED_LOCATION`)와 안드로이드 속도(`CAR_SPEED`)는 'dangerous' 등급이라 실행 중에 허락을 받는다.
- '다른 앱 위에 표시'는 설정 화면에서 따로 허용한다.

### SDK 사용 순서 (공통)

1. 만들기: `Vehicle(context)`, `FusedLocation(context)`, `TextToSpeech(context, Mode.ON_DEVICE)`
2. 시작: `initialize()`
3. 값 받기: `registerXxx(listener)` 또는 `getXxx(onComplete, onFailed)`. 결과는 다른 스레드에서 올 수 있어서 화면 글자는 메인 스레드에서 바꾼다.
4. 끝: `unregisterXxx(listener)` → `release()`
